## Findings (by severity)

### MEDIUM

**M1 — Two design elements have no implementing action item: the `memlens.meta`
header event and the `atexit`-style flush hook.**
Design ("Trace format", "Writer") requires a `memlens.meta` header recording
program/pid/start-time/version, and flushing "on `Drop` of a `LensSession` guard
*and* via an `atexit`-style hook." Task 1.2.2 covers only the `LensSession` guard;
no task emits `meta`. Without `meta` the schema in 1.1.3 is incomplete and the
viewer has no program identity to display; without the atexit hook, traces from
programs that never drop the guard are silently truncated.
*Fix:* extend 1.2.2 to "…`LensSession` flush guard + atexit-style flush hook; emit
`memlens.meta` header on session start", and ensure 1.1.3's schema includes `meta`
and `loss` shapes.

**M2 — Bolt 1.2 is oversized for one session.**
It contains the unit's only `unsafe` code (full `GlobalAlloc` impl), the reentrancy
guard, the locked writer, a proptest harness with a custom ops strategy, plus R7a/b
failure-injection tests, the R6 no-trace check, and an `nm`-based symbol-absence
script. That is the hardest code in the unit stacked with five distinct test
surfaces — and this is a teaching repo where the allocator is itself a lesson.
*Fix:* split 1.2.4 into its own bolt ("failure paths + feature-off verification"),
renumbering the macros bolt; 1.2 then ends cleanly at "R1 green."

**M3 — [P] rigor is asymmetric: ≥256 cases and `proptest-regressions/` committed
are stated only for the replay bolt (2.1.3), not for R1 in bolt 1.2.**
1.2.3's done-criterion is just "R1 green." Relying on the end-of-unit operations
checklist means the 1.2.3 commit can land green at default settings with no
regression corpus committed — violating the constitution's per-property rule at
the commit where it matters.
*Fix:* append "≥256 cases; `proptest-regressions/` committed" to 1.2.3.

### LOW

**L4 — R8's [E] verification is weaker than design specifies.** 1.1.3's "schema
round-trip [E] test" checks serde structs against themselves; design's verification
strategy says "schema validation against `memlens.v1.json`" — i.e., a *real emitted
trace file* validated against the registered schema. At 1.1.3 no trace exists yet.
*Fix:* add a small action item after bolt 1.3 (or fold into 1.3.2): validate a
fixture-produced `.jsonl` against `datalake/schema/memlens.v1.json`.

**L5 — R4 covers "scope **or variable**" but 1.3.2's fixture only names scope
enter/exit ordering.** `lens_var!`/`lens_drop!` labeling is never tested by name,
and no capture-side check exists that `lens_move!`/`lens_borrow!` actually emit
marker events (R12's raw material) before the viewer bolt depends on them.
*Fix:* extend 1.3.2's fixture to assert var/drop label events and marker presence.

**L6 — Unstated cross-crate test dependency.** 2.1.1/2.1.2 consume
"harness-generated traces" whose generator (the `Op` strategy) is written in
`crates/memlens`'s tests at 1.2.1. The plan doesn't say how `memlens-replay` gets
them — shared test-util crate, dev-dependency, or checked-in trace files.
*Fix:* one line in the 2.1 bolt header naming the mechanism (e.g., "harness lifted
to a shared dev-dependency" or "traces regenerated by running the 1.2 harness").

**L7 — Operations checklist deviates from the template silently.** "on the real AWS
target" was dropped and the teardown line removed. Both are *correct* adaptations
(R11: no server, no AWS in this unit), but the template rule is "note deviations
inline."
*Fix:* add "(no AWS resources in this unit per R11 — teardown N/A)".

**L8 — REQ-range headers are slightly sloppy, weakening grep traceability.** Main
task 4 claims "R9–R15", sweeping in R14b (actually done at 1.1.2); main tasks 1 and
2 both claim R2 without distinguishing harness vs checker roles.
*Fix:* task 4 header → "(R9–R13, R14a, R15, L1–L5)"; annotate R2 as "R2 (harness)"
in task 1 and "R2 (validator)" in task 2.

**L9 — Two action items are plausibly two commits each.** 1.2.3 (reentrancy guard
+ full `unsafe GlobalAlloc` + R1 green) and 3.2.1 (timeline canvas + scrubber +
live-set table).
*Fix:* split, or accept knowingly — the parent bolts remain the real checkpoints.
